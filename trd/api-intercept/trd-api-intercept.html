▶Consultant Notes

Compliance → detection service mapping:

  • PCI-DSS: DLP with card data patterns is mandatory. Block, do not just alert.
  • HIPAA: DLP with PHI patterns (names + diagnoses, MRNs, DOBs). Masking is often preferred over blocking for internal apps.
  • GDPR: Data residency matters — use the EU endpoint. DLP for EU citizen PII.
  • SOC 2: Audit log retention requirements. Flag for Day-2 appendix — the customer will need to configure SIEM forwarding.

Data residency: The endpoint region locks where scan payloads are processed. A US-endpoint key cannot be used against the EU endpoint — they must generate a new key and use the EU endpoint for all EU-regulated data.

▶Consultant Notes

Token sizing: Over-provisioning is safe — unused tokens don't carry over but the quota can be increased without re-provisioning. Under-provisioning causes the application to hit the monthly quota mid-cycle and scanning stops. Err high by 20–30% on first deployment.

Calculation example: 10,000 requests/day × 2,000 average characters/request × 2 (prompt + response) × 30 days = ~300 million characters ÷ 4 = ~75 million tokens = 0.075 billion/month. Round up significantly for variable-length applications.

Credit conflict check: If the customer has existing Network Intercept or Red Teaming deployments, confirm the credit pool is large enough for all products combined. Credits are shared at the pool level.

▶Consultant Notes

Profile name is the most critical field: It is typed into every API request as profile_name. A mismatch between what's in the code and what's in SCM returns a "profile not found" error. Agree on a naming convention now and document it.

Latency-sensitive applications: For real-time (<500ms) apps, recommend enabling only the highest-priority detection services first (Prompt Injection + DLP), running for 1–2 weeks to measure latency impact, then adding additional services. Each service adds approximately 20–80ms.

Fail-open vs. fail-safe: For security-critical applications (external-facing, handling PII), default to fail-safe. For internal productivity tools with high availability requirements, discuss fail-open with the security lead and document the decision.

Sync vs. Async Decision

Synchronous scanning is required for inline blocking — it holds the request until a verdict is returned. Asynchronous scanning is appropriate for logging/audit use cases, batch processing, or payloads over 2 MB. Most production deployments that need to block threats use synchronous mode.

API Key Region Lock

API keys are locked to the region where they were generated. A key generated for the US region returns 403 Forbidden when used against the EU endpoint. Key rotation procedure: Generate the new key first, deploy it, verify scanning works, then revoke the old key. Both keys are valid simultaneously until explicit revocation — this avoids downtime during rotation.
