▶Consultant Notes

Network Intercept vs. API Intercept decision: The key differentiator is whether the customer can modify application code. If they can't (third-party apps, legacy systems, SaaS), Network Intercept is required. If they can, API Intercept may be simpler (no infrastructure required). Many deployments use both: Network Intercept for broad network coverage, API Intercept for granular per-request scanning.

Brownfield vs. greenfield impact: Existing Panorama environments can use the Panorama-Managed deployment model, which reuses existing management infrastructure. Greenfield customers should default to SCM management for the fastest path to value.

Timeline reality: Network Intercept involves real infrastructure deployment. Terraform runs, cloud resource creation, and route table configuration take time. Budget minimum 2–3 sessions for deployment alone, not counting security profile configuration and validation.

▶Consultant Notes

Default recommendation for new deployments: Auto-Execute (AWS/Azure, SCM managed) gives the fastest time-to-value with zero Terraform work. The only constraint is that AWS Auto-Execute requires an existing Transit Gateway.

When to choose SCM Terraform Download: Customer needs GCP support, wants Panorama management option, or needs specific infrastructure control (custom VPC design, existing TGW integration, non-standard routing).

Panorama-Managed adds complexity: Verify CloudConnector Plugin 2.1.0 is installed before the deployment session. The SCM UI shows "Not Deployed" status for Panorama-managed templates — this is expected. Verify by checking the "Managed By" column.

Private Cloud / Manual Bootstrap: Budget extra time for bootstrap validation. The show system bootstrap status and show system info | match model commands are the authoritative verification steps. Expired PINs are the #1 blocker in these paths.

▶Consultant Notes

Annotation gotcha: The namespace-level annotation value ns-secure/bypassfirewall is misleading — it does NOT bypass the firewall. It instructs PAN-CNI to redirect pod traffic through the firewall for subnet-based inspection. This is a legacy naming artifact.

Azure dual virtual router requirement: Azure K8s deployments require two logical routers (vr-private and vr-public) because the Azure health probe IP 168.63.129.16/32 fails with a single router. Ensure this is captured when configuring the firewall for Azure K8s.

Docker MTU: Enabling panredirect reduces effective MTU to 1440 (GENEVE overhead). If Docker is used on protected workloads with default 1500 MTU, containers will have connectivity issues. Flag this for the workload admin.
