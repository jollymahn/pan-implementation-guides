GitHub Actions: Prisma AIRS Model Security

Add pre-deployment AI model scanning to GitHub Actions CI/CD pipelines using the Prisma AIRS Model Security SDK

Phase 1 Prerequisites Phase 2 Credentials Phase 3 Workflow Phase 4 Scan Config Phase 5 Verify
Model Security, Not Runtime Security

This guide integrates Prisma AIRS Model Security: pre-deployment scanning of AI model files (weights, binaries, configs) before they reach production infrastructure. This is different from AI Runtime Security, which scans prompts and responses at inference time.

Model Security uses OAuth2 client credentials (Client ID + Client Secret from a Prisma Cloud Service Account), not an AIRS API key. The authentication flow, SDK, and API endpoints are distinct from the Runtime Security integrations covered in the other AIRS guides.

Architecture Overview

The GitHub Actions integration adds a security gate to the CI/CD pipeline. When an AI model configuration changes, the workflow authenticates with Prisma AIRS via OAuth2, installs the Model Security SDK from a private PyPI repository, and scans the model. A scan result of ALLOWED permits deployment; BLOCKED halts the pipeline and prevents the model from reaching production.

What Gets Scanned

Prisma AIRS Model Security evaluates AI model files for:

  • Model provenance and supply chain risks — verifying model source and integrity
  • Known vulnerabilities — checking against CVEs and security advisories
  • Malicious payloads — detecting embedded malicious code or backdoors in model weights
  • Compliance violations — ensuring models meet organizational security policies
  • Training data risks — identifying potential data poisoning indicators

The CI/CD pipeline authenticates with Prisma AIRS using OAuth2 client credentials from a dedicated service account.

▶ Step 3.2: Create the PyPI Authentication Script

The Model Security SDK is distributed through a private PyPI repository. This script authenticates with the Prisma AIRS token endpoint to obtain an access token, then uses that token to retrieve the private PyPI URL.

Create scripts/get_pypi_url.sh:

#!/bin/bash
#
# Model Security Private PyPI Authentication Script
# Authenticates with SCM and retrieves PyPI repository URL
#

set -euo pipefail

# Check required environment variables
: "${MODEL_SECURITY_CLIENT_ID:?Error: MODEL_SECURITY_CLIENT_ID not set}"
: "${MODEL_SECURITY_CLIENT_SECRET:?Error: MODEL_SECURITY_CLIENT_SECRET not set}"
: "${TSG_ID:?Error: TSG_ID not set}"

# Set default endpoints
API_ENDPOINT="${MODEL_SECURITY_API_ENDPOINT:-https://api.sase.paloaltonetworks.com/aims}"
TOKEN_ENDPOINT="${MODEL_SECURITY_TOKEN_ENDPOINT:-https://auth.apps.paloaltonetworks.com/oauth2/access_token}"

# Get SCM access token via OAuth2 client credentials
TOKEN_RESPONSE=$(curl -sf -X POST "$TOKEN_ENDPOINT" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -u "$MODEL_SECURITY_CLIENT_ID:$MODEL_SECURITY_CLIENT_SECRET" \
    -d "grant_type=client_credentials&scope=tsg_id:$TSG_ID") || {
    echo "Error: Failed to obtain SCM access token" >&2
    exit 1
}

SCM_TOKEN=$(echo "$TOKEN_RESPONSE" | jq -r '.access_token')
if [[ -z "$SCM_TOKEN" || "$SCM_TOKEN" == "null" ]]; then
    echo "Error: Failed to extract access token from response" >&2
    exit 1
fi

# Use access token to retrieve private PyPI URL
PYPI_RESPONSE=$(curl -sf -X GET "$API_ENDPOINT/mgmt/v1/pypi/authenticate" \
    -H "Authorization: Bearer $SCM_TOKEN") || {
    echo "Error: Failed to retrieve PyPI URL" >&2
    exit 1
}

PYPI_URL=$(echo "$PYPI_RESPONSE" | jq -r '.url')
if [[ -z "$PYPI_URL" || "$PYPI_URL" == "null" ]]; then
    echo "Error: Failed to extract PyPI URL from response" >&2
    exit 1
fi

echo "$PYPI_URL"

Make the script executable:

chmod +x scripts/get_pypi_url.sh
OAuth2 Authentication Flow

The script performs two API calls: (1) POST to the token endpoint at https://auth.apps.paloaltonetworks.com/oauth2/access_token with client credentials to get an access token, then (2) GET to the API endpoint's /mgmt/v1/pypi/authenticate path using that token to retrieve the private PyPI URL. The jq tool must be available on the runner.

Verification

The file scripts/get_pypi_url.sh exists, is executable, and contains the OAuth2 authentication logic.

▶ Step 3.3: Create the Model Scan Script

The scan script loads the model configuration, initializes the Model Security SDK client, and calls the scan API. A result of BLOCKED causes a non-zero exit, which fails the GitHub Actions job and prevents deployment.

Create scripts/scan_model.py:

#!/usr/bin/env python3
"""
Prisma AIRS Model Security Scanner

Scans an AI model against Palo Alto Prisma AIRS security policies
using the official Model Security SDK. Exits non-zero if the model
fails the security assessment, blocking the CI/CD pipeline.
"""

import argparse
import os
import sys

import yaml
from dotenv import load_dotenv
from model_security_client.api import ModelSecurityAPIClient

load_dotenv()


def print_scan_results(result, model_name):
    """Pretty-print the scan results for CI log visibility."""
    print()
    print("=" * 64)
    print("  PRISMA AIRS MODEL SECURITY SCAN RESULTS")
    print("=" * 64)
    print(f"  Model:        {model_name}")
    print(f"  Scan UUID:    {getattr(result, 'uuid', 'N/A')}")
    print(f"  Outcome:      {result.eval_outcome}")
    print(f"  Summary:      {getattr(result, 'eval_summary', 'N/A')}")
    print(f"  Sec. Group:   {getattr(result, 'security_group_name', 'N/A')}")
    print(f"  Rules:        {getattr(result, 'enabled_rule_count_snapshot', 'N/A')}")
    print(f"  Files Scanned:{getattr(result, 'total_files_scanned', 'N/A')}")
    print(f"  Files Skipped:{getattr(result, 'total_files_skipped', 'N/A')}")

    violations = (
        getattr(result, 'rule_violations', None)
        or getattr(result, 'findings', [])
    )
    if violations:
        print(f"  Violations:   {len(violations)}")
        for v in violations:
            severity = getattr(v, 'severity', getattr(v, 'level', 'unknown'))
            desc = getattr(v, 'description', getattr(v, 'rule_name', 'No description'))
            print(f"    [{str(severity).upper()}] {desc}")

    print("=" * 64)
    print()


def main():
    parser = argparse.ArgumentParser(
        description="Scan an AI model with Prisma AIRS Model Security"
    )
    parser.add_argument(
        "--config", required=True,
        help="Path to the model configuration YAML file",
    )
    args = parser.parse_args()

    with open(args.config) as f:
        config = yaml.safe_load(f)

    if not config.get("security", {}).get("scan_enabled", True):
        print("Security scan is disabled in model config. Skipping.")
        sys.exit(0)

    # Allow overriding security_profile_id from environment variable
    profile_id = os.environ.get("MODEL_SECURITY_PROFILE_ID")
    if profile_id:
        config.setdefault("security", {})["security_profile_id"] = profile_id

    security_group_uuid = config["security"]["security_profile_id"]
    if not security_group_uuid:
        print("ERROR: No security_profile_id configured.")
        sys.exit(1)

    model_name = config["model"]["huggingface_id"]
    model_uri = f"https://huggingface.co/{model_name}"
    api_endpoint = os.environ.get(
        "MODEL_SECURITY_API_ENDPOINT",
        "https://api.sase.paloaltonetworks.com/aims",
    )

    print("Initializing Prisma AIRS Model Security SDK...")
    client = ModelSecurityAPIClient(base_url=api_endpoint)

    labels = {
        "deployment_target": "vertex_ai",
        "machine_type": config["deployment"]["machine_type"],
        "version": config["model"].get("version", "unknown").replace(".", "-"),
        "pipeline": "github-actions",
    }

    print(f"Scanning model: {model_name}")
    print(f"  URI: {model_uri}")
    print(f"  Security Group: {security_group_uuid}")
    print(f"  Labels: {labels}")

    result = client.scan(
        security_group_uuid=security_group_uuid,
        model_uri=model_uri,
        labels=labels,
    )

    print_scan_results(result, model_name)

    outcome = str(result.eval_outcome)
    if "BLOCKED" in outcome:
        print("BLOCKED: Model blocked by Prisma AIRS security policy.")
        print("The model will NOT be deployed.")
        sys.exit(1)
    elif "ALLOWED" in outcome:
        print("ALLOWED: Model approved by Prisma AIRS security policy.")
        print("The model is cleared for deployment.")
    else:
        print(f"WARNING: Unexpected scan outcome '{outcome}'. Blocking deployment.")
        sys.exit(1)


if __name__ == "__main__":
    main()
Verification

The file scripts/scan_model.py exists. Running python scripts/scan_model.py --help outputs the argument parser usage without errors (assuming dependencies are installed).

▶ Step 3.4: Create the GitHub Actions Workflow

The workflow file defines the CI/CD pipeline. It triggers on changes to the model configuration file, runs the security scan, and conditionally deploys the model.

Create .github/workflows/model-security-scan.yml:

name: Model Security Scan & Deploy

on:
  push:
    branches: [main]
    paths:
      - 'config/model-config.yaml'
  pull_request:
    branches: [main]
    paths:
      - 'config/model-config.yaml'
  workflow_dispatch:

jobs:

  # Detect whether the model config file changed
  detect-changes:
    name: Detect Model Changes
    runs-on: ubuntu-latest
    outputs:
      model_changed: ${{ steps.filter.outputs.model }}
    steps:
      - uses: actions/checkout@v4

      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            model:
              - 'config/model-config.yaml'

  # ── Prisma AIRS Model Security Scan ──────────────────────────
  # This job authenticates with Prisma AIRS via OAuth2,
  # installs the Model Security SDK from a private PyPI,
  # and scans the model. BLOCKED = pipeline failure.
  security-scan:
    name: Prisma AIRS Model Security Scan
    needs: detect-changes
    if: >
      needs.detect-changes.outputs.model_changed == 'true'
      || github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      # Authenticate and get private PyPI URL
      - name: Get Model Security SDK PyPI URL
        id: pypi
        env:
          MODEL_SECURITY_CLIENT_ID: ${{ secrets.MODEL_SECURITY_CLIENT_ID }}
          MODEL_SECURITY_CLIENT_SECRET: ${{ secrets.MODEL_SECURITY_CLIENT_SECRET }}
          MODEL_SECURITY_API_ENDPOINT: ${{ secrets.MODEL_SECURITY_API_ENDPOINT }}
          TSG_ID: ${{ secrets.TSG_ID }}
        run: echo "url=$(bash scripts/get_pypi_url.sh)" >> "$GITHUB_OUTPUT"

      # Install SDK from private PyPI
      - name: Install dependencies
        run: |
          pip install -r requirements.txt
          pip install "model-security-client[all]" \
            --extra-index-url "${{ steps.pypi.outputs.url }}"

      # Run the scan — exits non-zero on BLOCKED
      - name: Run Prisma AIRS Model Security Scan
        env:
          MODEL_SECURITY_CLIENT_ID: ${{ secrets.MODEL_SECURITY_CLIENT_ID }}
          MODEL_SECURITY_CLIENT_SECRET: ${{ secrets.MODEL_SECURITY_CLIENT_SECRET }}
          MODEL_SECURITY_API_ENDPOINT: ${{ secrets.MODEL_SECURITY_API_ENDPOINT }}
          MODEL_SECURITY_PROFILE_ID: ${{ secrets.MODEL_SECURITY_PROFILE_ID }}
          TSG_ID: ${{ secrets.TSG_ID }}
        run: python scripts/scan_model.py --config config/model-config.yaml

  # ── Deploy (replace with your infrastructure) ────────────────
  deploy-model:
    name: Deploy Model
    needs: security-scan
    if: >
      (github.event_name == 'push' && github.ref == 'refs/heads/main')
      || github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: echo "Add your deployment logic here"
Workflow Triggers

The workflow triggers on three events: (1) a push to main that modifies config/model-config.yaml, (2) a pull request targeting main with the same path filter, and (3) a manual workflow_dispatch. On pull requests, only the scan runs; deployment is skipped. On pushes to main, both scan and deploy run if the scan passes.

Verification

The file .github/workflows/model-security-scan.yml exists. Navigate to the repository's Actions tab in GitHub, and the workflow Model Security Scan & Deploy appears in the left sidebar.

Troubleshooting

▶ Common Issues and Resolutions
IssueCauseResolution
get_pypi_url.sh fails with Failed to obtain SCM access token Invalid Client ID, Client Secret, or TSG ID Verify the MODEL_SECURITY_CLIENT_ID, MODEL_SECURITY_CLIENT_SECRET, and TSG_ID secrets match the values from the service account in Strata Cloud Manager.
SDK installation fails with pip install error Private PyPI URL was not retrieved in the previous step Check the Get Model Security SDK PyPI URL step log. If the PyPI URL step failed silently, the subsequent pip install cannot find the model-security-client package.
Scan returns unexpected BLOCKED result Security profile rules are more restrictive than expected Check the MODEL_SECURITY_PROFILE_ID points to the intended security profile. Review the profile's rules in Strata Cloud Manager and adjust thresholds.
Workflow does not trigger on push The changed file does not match the paths filter The workflow triggers only on changes to config/model-config.yaml. Confirm the file path matches exactly. Use workflow_dispatch for manual testing.
jq: command not found The runner image does not include jq The ubuntu-latest runner includes jq by default. If using a custom runner, add sudo apt-get install -y jq before the PyPI authentication step.
Scan passes but deploy job does not run The deploy job runs only on pushes to main or manual dispatch Pull request triggers run the scan only. Merge the PR to main to trigger the deploy job.
