Jenkins: Prisma AIRS Model Security

Add pre-deployment AI model scanning to Jenkins Declarative Pipelines using the Prisma AIRS Model Security SDK

Phase 1 Prerequisites Phase 2 Credentials Phase 3 Pipeline Phase 4 Scan Config Phase 5 Verify
Model Security, Not Runtime Security

This guide integrates Prisma AIRS Model Security — pre-deployment scanning of AI model files (weights, binaries, configs) before they reach production infrastructure. This is different from AI Runtime Security, which scans prompts and responses at inference time.

Model Security uses OAuth2 client credentials (Client ID + Client Secret from a Prisma Cloud Service Account), not an AIRS API key. The authentication flow, SDK, and API endpoints are distinct from the Runtime Security integrations.

Architecture Overview

The Jenkins integration adds a security gate to the Declarative Pipeline. When a model configuration change is detected via SCM polling (or manual trigger), the pipeline authenticates with Prisma AIRS via OAuth2, installs the Model Security SDK from a private PyPI repository, and scans the model. A result of ALLOWED permits deployment; BLOCKED fails the pipeline stage and prevents the model from reaching production.

What Gets Scanned

Prisma AIRS Model Security evaluates AI model files for:

  • Model provenance and supply chain risks — verifying model source and integrity
  • Known vulnerabilities — checking against CVEs and security advisories
  • Malicious payloads — detecting embedded malicious code or backdoors in model weights
  • Compliance violations — ensuring models meet organizational security policies
  • Training data risks — identifying potential data poisoning indicators

  2. Click Add > Add Service Account.

Jenkins stores credentials in its built-in Credentials store. The Declarative Pipeline references these by their Credential ID using the withCredentials binding.

  1. Navigate to Manage Jenkins > Manage Credentials.
  2. Select the appropriate scope (e.g., Jenkins > Global credentials).
  3. Click Add Credentials and create each credential listed below.

Credential Scope Matters

Ensure credentials are created in a scope accessible to the pipeline job. If using folder-level credentials, the pipeline job must reside within that folder. Global credentials are accessible to all jobs.

Different From Runtime Security Credentials

These credentials are not the same as PRISMA_AIRS_API_KEY, PRISMA_AIRS_PROFILE_NAME, or PRISMA_AIRS_URL used by AI Runtime Security integrations. Model Security uses OAuth2 client credentials and the Model Security SDK.

▶ Step 3.2: Create the Supporting Scripts

The pipeline requires two scripts: get_pypi_url.sh for OAuth2 authentication and PyPI URL retrieval, and scan_model.py for the model security scan. These scripts are identical to the GitHub Actions versions with one difference: the pipeline label is set to jenkins.

Create scripts/get_pypi_url.sh:

#!/bin/bash
set -euo pipefail

: "${MODEL_SECURITY_CLIENT_ID:?Error: MODEL_SECURITY_CLIENT_ID not set}"
: "${MODEL_SECURITY_CLIENT_SECRET:?Error: MODEL_SECURITY_CLIENT_SECRET not set}"
: "${TSG_ID:?Error: TSG_ID not set}"

API_ENDPOINT="${MODEL_SECURITY_API_ENDPOINT:-https://api.sase.paloaltonetworks.com/aims}"
TOKEN_ENDPOINT="${MODEL_SECURITY_TOKEN_ENDPOINT:-https://auth.apps.paloaltonetworks.com/oauth2/access_token}"

# OAuth2 client credentials flow
TOKEN_RESPONSE=$(curl -sf -X POST "$TOKEN_ENDPOINT" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -u "$MODEL_SECURITY_CLIENT_ID:$MODEL_SECURITY_CLIENT_SECRET" \
    -d "grant_type=client_credentials&scope=tsg_id:$TSG_ID") || {
    echo "Error: Failed to obtain SCM access token" >&2
    exit 1
}

SCM_TOKEN=$(echo "$TOKEN_RESPONSE" | jq -r '.access_token')
if [[ -z "$SCM_TOKEN" || "$SCM_TOKEN" == "null" ]]; then
    echo "Error: Failed to extract access token" >&2
    exit 1
fi

PYPI_RESPONSE=$(curl -sf -X GET "$API_ENDPOINT/mgmt/v1/pypi/authenticate" \
    -H "Authorization: Bearer $SCM_TOKEN") || {
    echo "Error: Failed to retrieve PyPI URL" >&2
    exit 1
}

PYPI_URL=$(echo "$PYPI_RESPONSE" | jq -r '.url')
if [[ -z "$PYPI_URL" || "$PYPI_URL" == "null" ]]; then
    echo "Error: Failed to extract PyPI URL" >&2
    exit 1
fi

echo "$PYPI_URL"

Create scripts/scan_model.py with the same content as the GitHub Actions scan script, changing the pipeline label:

labels = {

Make the shell script executable:

▶ Step 3.3: Create the Jenkinsfile

The Jenkinsfile defines a Declarative Pipeline with three stages: change detection, security scan, and deployment. The scan stage uses withCredentials to inject secrets as environment variables.

Create Jenkinsfile at the repository root:

pipeline {
    agent any

    options {
        timestamps()
        timeout(time: 60, unit: 'MINUTES')
        disableConcurrentBuilds()
    }

    triggers {
        pollSCM('H/5 * * * *')   // Poll for changes every 5 minutes
    }

    parameters {
        booleanParam(
            name: 'FORCE_RUN',
            defaultValue: false,
            description: 'Run the pipeline even if model config has not changed'
        )
        booleanParam(
            name: 'SKIP_DEPLOY',
            defaultValue: false,
            description: 'Run security scan only, skip deployment'
        )
    }

    environment {
        CONFIG_FILE = 'config/model-config.yaml'
    }

    stages {

        stage('Detect Changes') {
            steps {
                script {
                    env.MODEL_CHANGED = 'false'
                    if (params.FORCE_RUN) {
                        echo 'FORCE_RUN enabled — skipping change detection.'
                        env.MODEL_CHANGED = 'true'
                        return
                    }
                    def changes = currentBuild.changeSets.collectMany {
                        it.items.collectMany { item ->
                            item.affectedFiles.collect { it.path }
                        }
                    }
                    if (changes.any { it == 'config/model-config.yaml' }) {
                        echo 'Model config changed — proceeding with scan.'
                        env.MODEL_CHANGED = 'true'
                    } else {
                        echo 'No model config changes detected.'
                    }
                }
            }
        }

        // ── Prisma AIRS Model Security Scan ──────────────────
        stage('Prisma AIRS Model Security Scan') {
            when {
                expression { env.MODEL_CHANGED == 'true' }
            }
            steps {
                withCredentials([
                    string(credentialsId: 'model-security-client-id',
                           variable: 'MODEL_SECURITY_CLIENT_ID'),
                    string(credentialsId: 'model-security-client-secret',
                           variable: 'MODEL_SECURITY_CLIENT_SECRET'),
                    string(credentialsId: 'model-security-api-endpoint',
                           variable: 'MODEL_SECURITY_API_ENDPOINT'),
                    string(credentialsId: 'model-security-profile-id',
                           variable: 'MODEL_SECURITY_PROFILE_ID'),
                    string(credentialsId: 'tsg-id',
                           variable: 'TSG_ID'),
                ]) {
                    sh '''
                        echo "=== Setting up Python environment ==="
                        python3 -m venv .venv
                        . .venv/bin/activate

                        echo "=== Installing base dependencies ==="
                        pip install --quiet -r requirements.txt

                        echo "=== Authenticating with Prisma AIRS ==="
                        PYPI_URL=$(bash scripts/get_pypi_url.sh)

                        echo "=== Installing Model Security SDK ==="
                        pip install --quiet "model-security-client[all]" \
                            --extra-index-url "${PYPI_URL}"

                        echo "=== Running Model Security Scan ==="
                        python scripts/scan_model.py \
                            --config ${CONFIG_FILE}
                    '''
                }
            }
        }

        // ── Deploy (replace with your infrastructure) ────────
        stage('Deploy Model to Vertex AI') {
            when {
                allOf {
                    expression { env.MODEL_CHANGED == 'true' }
                    expression { !params.SKIP_DEPLOY }
                    expression {
                        env.GIT_BRANCH == 'main' ||
                        env.GIT_BRANCH == 'origin/main'
                    }
                }
            }
            steps {
                sh 'echo "Add your deployment logic here"'
            }
        }
    }

    // NOTE: The reference implementation includes a full 'Deploy Model to
    // Vertex AI' stage with GCP service account auth, gcloud CLI setup,
    // and a deploy_model.sh script, plus a 'Test Model Endpoint' stage.
    // See the source repository for the complete Jenkinsfile.

    post {
        success { echo 'Pipeline completed successfully.' }
        failure { echo 'Pipeline failed. Check logs above.' }
        always  { sh 'rm -rf .venv || true' }
    }
}

Pipeline Parameters

The pipeline exposes two parameters: FORCE_RUN bypasses change detection and runs the scan unconditionally; SKIP_DEPLOY runs the scan without triggering deployment (useful for testing scan rules). Access these via Build with Parameters in the Jenkins UI.

Virtual Environment Cleanup

The post.always block removes the Python virtual environment (.venv) after every build to prevent stale SDK versions from persisting on the agent. The SDK is reinstalled fresh on each run from the private PyPI.

Verification

The Jenkinsfile exists at the repository root. Create a Pipeline job in Jenkins, point it to the repository, and run Build with Parameters > FORCE_RUN: true. The Detect Changes stage should log FORCE_RUN enabled.

The model configuration file specifies which model to scan. Changes to this file are detected by SCM polling, triggering the pipeline.

▶ Step 4.3: Configure SCM Polling

The Jenkinsfile includes a pollSCM trigger that checks the repository for changes every 5 minutes. Adjust the cron expression in the Jenkinsfile to match the desired polling interval.

triggers {
    pollSCM('H/5 * * * *')   // Every 5 minutes (H adds distributed jitter)
}
Cron ExpressionIntervalUse Case
H/5 * * * *Every 5 minutesActive development with frequent model changes
H/15 * * * *Every 15 minutesStandard development cadence
H * * * *Every hourLow-frequency model updates
Note

The H prefix adds distributed jitter to prevent all Jenkins jobs from polling simultaneously. Replace H with a specific minute (e.g., */5) only if precise timing is required.

Verification

In the Jenkins job configuration page, the Poll SCM trigger shows the configured schedule. The Polling Log link (on the job page) shows recent poll activity.

Phase 5: Verification

▶ Step 5.1: Trigger the Pipeline

Trigger the pipeline using one of three methods.

Option A: Push a Configuration Change

  1. Edit config/model-config.yaml (e.g., update the version field).
  2. Commit and push. The next SCM poll cycle triggers the pipeline.

Option B: Manual Build with FORCE_RUN

  1. Open the Jenkins job page.
  2. Click Build with Parameters.
  3. Check FORCE_RUN and click Build.

Option C: Scan-Only Mode

  1. Click Build with Parameters.
  2. Check both FORCE_RUN and SKIP_DEPLOY.
  3. Click Build — the scan runs but the Deploy stage is skipped.
Verification

A new build appears in the Build History sidebar. The build is In Progress or Queued.

Troubleshooting

▶ Common Issues and Resolutions
IssueCauseResolution
get_pypi_url.sh fails with Failed to obtain SCM access token Invalid Client ID, Client Secret, or TSG ID Verify the model-security-client-id, model-security-client-secret, and tsg-id credentials in Jenkins match the values from the service account.
SDK installation fails Private PyPI URL was not retrieved in the previous step Check the Authenticating with Prisma AIRS output in the console log. If the PyPI URL step failed, the SDK cannot be installed.
Scan returns unexpected BLOCKED Security profile rules are more restrictive than expected Verify model-security-profile-id points to the intended profile. Review rules in Strata Cloud Manager.
Credentials not found Credentials are in a scope not accessible to the pipeline job Verify credentials are in the correct Jenkins scope (global or folder-level). The pipeline job must be within the credential scope.
SCM polling not triggering Poll schedule misconfigured or repository URL inaccessible Check the pollSCM schedule in the Jenkinsfile (H/5 * * * *). Verify the repository URL in the job configuration is correct and reachable from the Jenkins server.
python3: command not found Python is not installed or not in PATH on the Jenkins agent Install Python 3.11+ on the agent. Alternatively, use a Docker agent with Python pre-installed: agent { docker { image 'python:3.11-slim' } }.
