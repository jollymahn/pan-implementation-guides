Organization Registration and Gateway URLs

Chapter 1 of 13. Licensing the gateway, confirming the organization that everything else hangs from, and pointing the console at a self-hosted endpoint

Configuration Hub Next: Authentication Connectivity Reference

What an organization is

The organization is the highest level of abstraction in the AI Gateway. It contains every user, workspace, integration, guardrail, and key in your deployment, and several settings exist only at this level.

  • Users and workspaces — every account and every workspace belongs to exactly one organization.
  • Single sign-on — SSO is configured per organization, not per workspace.
  • Admin keys — owners and organization admins hold keys that reach across all workspaces.
  • Self-hosted control plane connection — a privately deployed gateway connects to the control plane at the organization level.
  • Organization switcher — a user with access to more than one organization moves between them in the console.

Getting this chapter right matters because the organization identifier appears in configuration you will generate later, and because the SSO and provisioning work in chapter 2 applies to the organization as a whole.

Prerequisites

Before starting you need:

  • A Strata Cloud Manager tenant you can sign in to
  • The Organization Owner role, or an account that will become the owner during activation
  • Access to the Customer Support Portal for the deployment profile step
  • Flex credits available on the tenant, or a credit pool you can draw against
  • An estimate of monthly token consumption, which step 1 shows you how to build
Already licensed and activated?

If the AI Gateway card already appears in Strata Cloud Manager and you can open the gateway console, skip to step 2. Step 1 exists so this chapter stands on its own for a tenant that has not been activated yet.

Step 1 — License and activate the gateway

Licensing is token-based and is sized against expected monthly consumption. The four steps below create the deployment profile, map it to your tenant, and confirm activation reached Strata Cloud Manager.

▶ Step 1.1: Size your license by monthly token consumption

All AI Gateway metering is token-based. Every AI transaction through the gateway (prompts, MCP interactions, and A2A traffic) draws down flex credits by token usage, and you license the instance against your maximum expected monthly token consumption.

The token conversion is the industry standard:

1 token = 4 characters of text

estimated monthly tokens = total characters sent and received per month / 4

billion tokens per month = estimated monthly tokens / 1,000,000,000

Example: 12,000,000,000 characters per month
  tokens   = 12,000,000,000 / 4 = 3,000,000,000
  billions = 3,000,000,000 / 1,000,000,000 = 3

To build the estimate, inventory the applications, agents, and MCP servers that will route through the gateway, and for each one approximate: requests per month, average prompt size (including system prompts and context), and average response size. Sum the character counts, divide by 4, and add headroom for growth.

Both directions count

Metering covers the full transaction, not just what you send. Long model responses and large context windows (retrieved documents, tool schemas, conversation history) dominate token counts in most real workloads.

Verification

You have a single number in billions of tokens per month (with growth headroom) to type into the Billion tokens per month field in the next step. Round up to a whole number of billions; enter 1 for anything under one billion. The field takes whole billions only, in steps of one billion, and rejects fractional values.

▶ Step 1.2: Create the deployment profile and allocate flex credits

The deployment profile is the licensing object that funds AI Gateway. You create it in the Customer Support Portal (not Strata Cloud Manager), from the credit pool that holds your flex credits. Creating it and finishing setup (next step) is what activates the gateway for your tenant.

  1. Log in to the Palo Alto Networks Customer Support Portal.
  2. In the left navigation, expand Products and select Software NGFW Credits. (Flex credits for every Software NGFW and Prisma AIRS product, AI Gateway included, come from the same pools, so this is the right page.)
  3. Locate the credit pool that will fund the gateway and click its name (or its row) to open the pool page; if several are listed, open the one with the most remaining credits. Item 8 shows how many credits this profile will draw; if that number exceeds the pool's remaining credits, close the dialog without creating the profile and repeat from this item with another pool. The pool page shows total credits, the allocated and consumed meters, the expiration date, and, at the bottom, the Current Deployment Profiles table.
  4. Before creating anything, scroll to the Current Deployment Profiles table. If a row with product type AI-GW and the Profile Name you chose (or planned to choose) already exists from an earlier attempt, do not create another; it already holds a credit allocation. Skip to Step 1.3 and use that row's Finish Setup link. An AI-GW row with a different name belongs to another deployment; leave it alone and create yours. If you created a profile by mistake, open the vertical ellipsis (More Options) at the far right of its row and select Delete; Palo Alto Networks documents this control for other Software NGFW credit profiles, including Prisma AIRS ones. If the menu offers no Delete, open an admin case in the Customer Support Portal or ask your account team to remove the profile and return its credits.
  5. Click Create New Profile (above the Current Deployment Profiles table).
  6. In the Create Deployment Profile: STEP 1 dialog, the products are laid out in labeled columns. Find the column headed Prisma AIRS: and click AI Gateway within it so its option is selected. The dialog calls this the firewall type because the same wizard provisions Software NGFW products; AI Gateway is not a firewall, and selecting it here is correct. Click Next.
  7. Complete the FORM stage:
    • Deployment — select the option matching your deployment model: Managed Service if you chose SaaS, Self Service (DIY) if you chose Hybrid. The field is informational and does not change the credit allocation or the usage limit; if undecided, choose Managed Service.
    • Profile Name — a descriptive name, for example AI-Gateway-Deployment-Profile.
    • Billion tokens per month — the billions figure you calculated in Step 1.1.
    • Bundled — no action needed. Strata Cloud Manager Pro is bundled with AI Gateway automatically and cannot be deselected. Its cost is included in the credit estimate you see in the next item, so that estimate covers more than AI Gateway alone.
    • Notes — optional.
  8. Click Calculate Estimated Cost. The dialog shows how many credits this profile will draw and how many remain available in the pool; this is the flex credit allocation.
  9. Click Create Deployment Profile. The dialog closes and returns you to the Software NGFW Credits credit pool page, with your new profile listed in the Current Deployment Profiles table at the bottom.

▶ Step 1.3: Map the deployment profile to a Tenant Service Group

Mapping the deployment profile to a Tenant Service Group (TSG) is the link that connects Strata Cloud Manager and the Strata Logging Service to your AI Gateway. The TSG you map becomes the AI Gateway organization. The activation form labels the TSG as the Tenant.

  1. On the same Software NGFW Credits credit pool page from Step 1.2, scroll to the Current Deployment Profiles table and click the Finish Setup link on your AI-GW profile row. If you navigated away after the last step, get back via Products → Software NGFW Credits and reopen the same pool. The Activate Subscriptions based on Deployment Profile(s) page opens.
  2. Under Select Customer Support Account, choose the support account used to create the deployment profile.
  3. Under Specify the Recipient, select the Tenant that will own the gateway. This is the TSG. To confirm which name is yours, open the hub with the account you used in the prerequisites above, select Common Services → Tenant Management, find the tenant you work in, and select the matching Tenant here. If only one tenant is listed, select it.
  4. Under Select Region, choose your region (for example, United States - Americas). The form will not proceed without it.
  5. Under Select Deployment Profile(s), check the AI Gateway profile you created (its services column reads Strata Cloud Manager Pro, AI Runtime Security Gateway). Profiles already associated with this tenant are pre-checked; leave them checked, so the selected count will read higher than one. Unchecking a pre-checked profile removes its association when you activate. Click Done.
  6. Leave Data Loss Prevention and Additional Services (including Cloud Identity Engine) at their pre-populated defaults; AI Gateway uses neither. A greyed-out DLP field is expected.
  7. Check Agree to the Terms and Conditions, then click Activate.

Step 2 — Confirm the organization and record its identifier

Activation creates an organization and makes the activating account its owner. Confirm both before configuring anything else, because an unexpected owner or a second organization created by a colleague will send the rest of this set into the wrong tenant.

▶ 2.1 — Open the organization settings
  1. Sign in to Strata Cloud Manager and open the AI Gateway.
  2. Go to Admin Settings → Organisation → General.

The General page holds the organization name, the identifier, and the Gateway URLs section used in step 3.

Verification

The General page loads and shows an organization name. If Admin Settings → Organisation is absent, your account is a member rather than an owner or admin, and the rest of this chapter will not be available to you.

▶ 2.2 — Record the Organisation ID

Copy the Organisation ID from the General page and store it with your deployment notes. Later chapters and several integrations reference it, and a self-hosted data plane carries it as an environment variable.

Two vendors, two spellings

The gateway spells its field Organisation ID. OpenAI spells its own field Organization ID. Both appear in a complete AI Gateway deployment and neither is a typo, so copy each one from the console that owns it.

Verification

You have the identifier recorded outside the console. Nothing in the console changes at this step.

▶ 2.3 — Confirm ownership

Check that the account holding the Owner role is the one your organization intends to own the deployment long term. Activation grants ownership to whoever completed it, which is often a consultant or a first responder rather than the eventual platform owner.

  1. In Admin Settings, open the user list for the organization.
  2. Confirm at least one Owner account exists and belongs to the customer rather than to a temporary account.
  3. Add a second owner if only one exists.
Add a second owner before going further

A single owner account is a single point of failure for the whole organization. Authentication settings, organization guardrails, and defaults are all owner-level changes, so losing that one account locks the configuration.

Verification

Two or more accounts show the Owner role, and at least one belongs to the customer.

Step 3 — Point the console at your gateway

The Gateway URLs settings tell the console which endpoint to use when it generates code snippets, runs playground completions, and builds MCP server endpoints. Both values are set once for the whole organization and apply to every workspace in it.

Hosted data plane? Skip this step.

Leaving both fields blank makes the console fall back to the hosted endpoints: https://aigw.portkey.ai/v1 for the gateway and https://aigw.portkey.ai/m for the MCP gateway. If you deployed the SaaS data plane, that fallback is what you want and step 3 has nothing for you to do.

▶ 3.1 — Set the Gateway URL
  1. Go to Admin Settings → Organisation → General.
  2. Scroll to the Gateway URLs section.
  3. In the Gateway URL field, enter the base URL of your self-hosted gateway, for example https://gateway.example.com.
  4. Click outside the field.

There is no save button. The value commits when the field loses focus.

The trailing path is normalized for you

Entering https://gateway.example.com and entering https://gateway.example.com/v1 produce the same result. The console always uses the /v1 form.

Verification

Open the Model Catalog or the Getting Started page and look at a generated code snippet. The baseURL shows your hostname rather than https://aigw.portkey.ai/v1.

▶ 3.2 — Set the MCP Gateway URL

Set this only if you run a self-hosted MCP gateway. The console uses it to build the endpoint for every MCP server registered in the organization.

  1. In the same Gateway URLs section, enter the base URL in the MCP Gateway URL field, for example https://mcp.example.com.
  2. Click outside the field.

An MCP server with the slug my-server then resolves to:

https://mcp.example.com/my-server/mcp
Verification

The value persists after a page reload. Chapter 10 confirms the endpoint end to end once an MCP server is registered, because an unregistered organization has no server slug to resolve.

▶ 3.3 — Clear a value you no longer want

Delete the URL from the field and click outside it. The console reverts to the hosted default for that field.

Verification

A freshly generated code snippet shows the hosted endpoint again.

Private and self-hosted management planes ignore this field

If you run a private or self-hosted deployment of the management plane, the gateway URL shown in the console comes from the INTERNAL_GATEWAY_URL or GATEWAY_BASE_URL environment variable set by whoever deployed it. Typing a value here has no effect. Ask your deployment administrator to change the variable instead.

Step 4 — Verify the foundation

▶ 4.1 — Confirm the chapter is complete

Work through this list before moving to chapter 2. Each item is checked in the console, not assumed.

  • The AI Gateway opens from Strata Cloud Manager without a licensing prompt.
  • Admin Settings → Organisation is reachable, which confirms your role.
  • The Organisation ID is recorded outside the console.
  • At least two accounts hold the Owner role.
  • For a self-hosted data plane, a generated code snippet carries your gateway hostname.
Verification

All five items hold. The organization now has an owner, an identity, and a known endpoint, which is everything chapter 2 needs to attach an identity provider to it.

Multiple organizations

A tenant can hold more than one organization, and a user granted access to several moves between them with the organization switcher. Separate organizations are a heavier boundary than separate workspaces: they share no users, no integrations, no guardrails, and no keys.

UseBoundaryWhen it fits
One organization, many workspacesShared SSO, shared integrations, per-team budgets and guardrailsTeams inside one company. This is the normal choice and the rest of this set assumes it.
Separate organizationsNo shared configuration of any kindA genuine legal or regulatory separation, or a managed service provider holding distinct customers.
Do not use a second organization to separate environments

Development, staging, and production belong in workspaces within one organization. Splitting them across organizations duplicates the identity provider configuration, the integrations, and the guardrails, and every later chapter in this set then has to be performed twice.
