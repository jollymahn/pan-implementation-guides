Prisma AIRS AI Gateway Deployment

Stand up the Prisma AIRS AI Gateway as your centralized security and observability layer for AI traffic (LLM prompts, MCP interactions, and agent-to-agent communication), license it with flex credits, and configure LLM integrations with workspace provisioning, budgets, rate limits, and model allowlists in Strata Cloud Manager

Guide Approach

This guide deploys the Prisma AIRS AI Gateway, the Palo Alto Networks native gateway managed through Strata Cloud Manager (SCM). You pick how the data plane runs once (SaaS, hosted by Palo Alto Networks, or Hybrid, hosted in your own Kubernetes cluster), and the guide tailors the enablement phase to that choice. The selector is sticky: choose it in any section and the whole page follows.

Design model: every AI interaction in your organization (LLM prompts, Model Context Protocol traffic, and agent-to-agent communication) routes through the gateway, which applies guardrails, budgets, rate limits, and model allowlists while logging everything to a single dashboard.

Deployment method: configuration-driven. The SaaS gateway needs no infrastructure at all; the Hybrid data plane is a containerized deployment installed with Helm charts and still managed centrally from SCM. No infrastructure-as-code is required for the SCM configuration itself.

Architecture Overview

AI Gateway provides a centralized security and observability layer for all AI traffic in your organization. It sits between your applications, agents, and MCP clients on one side and your LLM providers, MCP servers, and privately hosted models on the other. Strata Cloud Manager is the control plane: licensing, configuration, access control, and dashboards all live there.

High-level architecture, showing where each component sits:

▶ What the gateway secures — prompts, MCP, and A2A

The gateway monitors and audits three classes of AI traffic from a single dashboard:

  • LLM prompts — requests and responses between your applications and model providers.
  • MCP interactions — Model Context Protocol traffic between agents and MCP servers, including servers authenticated with API keys or static tokens via custom headers.
  • Agent-to-agent (A2A) communication — traffic exchanged directly between AI agents.

All three classes are metered by token consumption against your flex credit allocation, and all three appear in the unified AI Gateway dashboard.

Verification

You can name the three traffic classes the gateway secures and know that all of them are metered and logged the same way.

▶ Key capabilities in this release
  • Unified AI traffic visibility — monitor and audit all AI interactions across prompts, MCP, and A2A traffic from a single dashboard.
  • Flexible logging — event logs stream to SIEM and SOAR tools via OpenTelemetry-compatible endpoints; prompt logs are stored natively with 1-year retention and, on Hybrid deployments, can be exported to a customer-owned S3 bucket.
  • Guardrails — Basic and third-party guardrails are supported out of the box; Check Language and Detect Gibberish are included in the Basic tier.
  • Flex credit licensing — metered by token consumption (1 token equals 4 characters), with identical pricing across both deployment models.
  • SCM-managed — full lifecycle management through Strata Cloud Manager with role-based access control via SBAC.

Each tenant starts with a single default workspace. Multiple workspaces are supported, as is Strata Logging Service (SLS) integration for Threat Logs.

Verification

You understand the five capability pillars: visibility, logging, guardrails, flex credit licensing, and SCM management.

▶ Where AI Gateway ends and AI Runtime begins

AI Gateway is one pillar of Prisma AIRS, and its guardrails are intentionally scoped. Two detection families are not part of the gateway guardrail set:

  • PII detection — handled by AI Runtime, which provides advanced DLP.
  • Moderation — handled by AI Runtime, which provides advanced threat detection.

Palo Alto Networks routes those to AI Runtime because it provides more comprehensive threat detection and DLP capabilities than guardrails cover. If you need inline scanning for prompt injection, data leaks, or malicious content, pair the gateway with the AIRS API Intercept pillar.

Verification

You know which detections the gateway guardrails supply and which belong to AI Runtime, so nothing is assumed covered that is not.

Region availability

AI Gateway is initially available in the Americas region for both SaaS and Hybrid deployments. Check the official documentation for region expansion before planning a deployment elsewhere.

Choose Your Deployment Model

AI Gateway ships in two deployment models. The control plane is always SCM; the choice is where the data plane (the component your AI traffic actually flows through) runs. Pick once here and the rest of the guide follows your choice; the selection persists across the page and between visits.

The two models side by side:

Which path should I pick?
  • SaaS — the default. Choose it when you want zero infrastructure work, automatic scaling, and built-in high availability. It is enabled as soon as licensing completes.
  • Hybrid — choose it when AI traffic must stay inside your own environment (any public cloud, private cloud, or on-premises Kubernetes cluster), or when you need local prompt-log export to your own S3 bucket. You operate the data plane; SCM still manages it.

Pricing is identical for both models. There is no cost penalty for choosing one over the other, and no additional cost for using multiple gateways or distributing the data plane.

Phase 1: License & Activate

AI Gateway is licensed with flex credits and activated through a deployment profile in Strata Cloud Manager. This phase confirms your prerequisites, sizes your license, creates the deployment profile, and maps it to your tenant so the gateway lights up.

▶ Step 1.1: Confirm prerequisites

Two things must already be true before the AI Gateway tile will do anything useful:

  1. An activated AI Runtime Security license. If your organization has not activated Prisma AIRS yet, complete Activate Your AI Runtime Security License first.
  2. A cloud account onboarded and activated in Strata Cloud Manager, per Onboard and Activate a Cloud Account in SCM.

You also need flex credits available to allocate, and an SCM user with sufficient role-based (SBAC) permissions to create deployment profiles and manage the AI Security section.

Verification

You can log into Strata Cloud Manager, your AIRS license shows as active, and your cloud account appears as onboarded.

▶ Step 1.2: Size your license by monthly token consumption

All AI Gateway metering is token-based. Every AI transaction through the gateway (prompts, MCP interactions, and A2A traffic) draws down flex credits by token usage, and you license the instance against your maximum expected monthly token consumption.

The token conversion is the industry standard:

1 token = 4 characters of text

estimated monthly tokens = total characters sent and received per month / 4

To build the estimate, inventory the applications, agents, and MCP servers that will route through the gateway, and for each one approximate: requests per month, average prompt size (including system prompts and context), and average response size. Sum the character counts, divide by 4, and add headroom for growth.

Both directions count

Metering covers the full transaction, not just what you send. Long model responses and large context windows (retrieved documents, tool schemas, conversation history) dominate token counts in most real workloads.

Verification

You have a monthly token number (with growth headroom) to enter as Billion tokens per month on the deployment profile form in the next step.

▶ Step 1.3: Create the deployment profile and allocate flex credits

The deployment profile is the licensing object that funds AI Gateway. You create it in the Customer Support Portal (not Strata Cloud Manager), from the credit pool that holds your flex credits. Creating it and finishing setup (next step) is what activates the gateway for your tenant.

  1. Log in to the Palo Alto Networks Customer Support Portal.
  2. Select Products → Software NGFW Credits and locate the credit pool that will fund the gateway. The pool summary shows total credits, the allocated and consumed meters, and the expiration date.
  3. Click Create New Profile (above the Current Deployment Profiles table).
  4. In Create Deployment Profile: STEP 1, select AI Gateway as the firewall type (under the Prisma AIRS: column), then click Next.
  5. Complete the FORM stage:
    • Deployment — Managed Service (Palo Alto Networks hosts the data plane; the SaaS model) or Self Service (DIY) (you host the data plane; the Hybrid model).
    • Profile Name — a descriptive name, for example AI-Gateway-Deployment-Profile.
    • Billion tokens per month — your Step 1.2 estimate, converted to billions.
    • Bundled — Strata Cloud Manager Pro is included automatically and cannot be deselected.
    • Notes — optional.
  6. Click Calculate Estimated Cost. The dialog shows how many credits this profile will draw and how many remain available in the pool; this is the flex credit allocation.
  7. Click Create Deployment Profile.

What is a slug?

A slug is an identifier for a provider or integration within the AI Gateway. Provider slugs appear in the Model Catalog and are used in API calls to specify a particular provider, so pick a slug your developers will recognize in request paths and configs.

Custom headers are shared credentials

A custom header rides on every request through the integration and is shared by all users. Treat any token you place in one as an organization-wide credential: scope it minimally at the MCP server and rotate it on personnel or scope changes.

▶ Step 3.4: Configure a Pricing Adjust Multiplier

Pricing Adjustments apply a discount or markup multiplier to the integration so cost tracking reflects your effective rate with the provider. A multiplier of 1 leaves pricing unchanged, 0.8 applies a 20% discount, and 1.2 applies a 20% markup.

  1. Switch on the Pricing Adjustments toggle at the bottom of the details page. Leaving it off keeps list pricing; enable it only if you need to adjust cost tracking.
  2. Select the mode: Form (the default) for the most common token types, or JSON for the full multiplier shape, including reasoning, audio, image, and additional units.
  3. Enter the multiplier values for each token type you want to adjust.
  4. When the details page is complete, click Next: Choose Workspace.

This is especially useful for:

  • Negotiated Discounts — reflect enterprise contracts or committed-use rates from a provider on the corresponding integration.
  • Internal Cost Showback — apply a markup so the cost reported to internal teams or workspaces includes your platform overhead.
  • Custom Per-Integration Rates — maintain different effective pricing across multiple integrations of the same provider (for example, a discounted production integration alongside a standard-rate sandbox).

For a discount, convert the percentage to a multiplier:

multiplier = 1 - (discount% / 100)

Example: 10% discount on Default, 15% discount on Request Tokens
  Default        = 1 - (10 / 100) = 0.90
  Request Tokens = 1 - (15 / 100) = 0.85

Request Tokens use 0.85; Response Tokens, Cache Read Tokens,
and Cache Write Tokens inherit 0.90 from Default.
Verification

If your provider contract has negotiated rates, the multiplier matches the contract math (a 10% discount shows as 0.90). If not, the toggle stays off and reported costs use list pricing.

▶ Step 3.5: Set up workspace provisioning

Workspace provisioning determines which teams and projects can access this integration. This is crucial for maintaining security boundaries and ensuring teams only access approved AI resources. Sharing credentials with a workspace means:

  • That workspace sees the integration as an AI Provider in their Model Catalog.
  • They can use it immediately; there is no need to enter credentials again.
  • You can set different budgets and rate limits for each workspace.
  • You can revoke access at any time.
  1. On the Workspace Access, Budget & Rate Limits stage, check the box next to each workspace that gets access (the toolbar offers Select All, Deselect All, and a search filter).
  2. Optionally enable Automatically provision this integration for new workspaces: every workspace created in the future then receives this integration and its budget and rate limits. You can override or remove it anytime.
  3. Optionally, for each workspace, click Set Value (or select several and use Set Value for All Selected) to configure budget and rate limits, detailed in Steps 3.6 and 3.7.

▶ Step 3.6: Add budget limits

Budget limits on integrations manage your spending on AI providers and LLMs, acting as financial guardrails that prevent unexpected AI costs across your organization. These limits cascade down to all AI Providers created from this integration.

  1. In the workspace's Set Value panel (opened in Step 3.5), switch on Add Budget.
  2. Choose the limit type with the Request or Token selector:
    • Cost-based (USD) — a budget in dollars entered in the Budget Limit ($) field that, once reached, automatically expires the key to prevent further usage and overspending.
    • Token-based — a maximum number of tokens that can be consumed, controlling usage independent of cost fluctuations.
  3. Optionally fill the Alter Threshold ($) field with a dollar amount below the budget limit.
  4. Set the reset cadence dropdown:
    • No Periodic Reset — the budget limit applies until exhausted, with no automatic renewal.
    • Reset Weekly — resets at the beginning of each week (Sunday at 12 AM UTC).
    • Reset Monthly — resets on the 1st calendar day of the month at 12 AM UTC, irrespective of when the budget limit was set.

The Add Budget section appears in the Set Value panel shown in Step 3.5.

What Alter Threshold means

The field carries no description in the UI, but it maps to the underlying gateway platform's alert threshold (the on-screen label appears to be a typo). When spend crosses this amount, the gateway raises an alert without blocking traffic; requests are blocked only when the Budget Limit itself is reached. Example: a Budget Limit of 500 with a threshold of 400 warns at $400 of spend and cuts off at $500. A common practice is to set it at 80% of the budget.

Key considerations for budget limits:

  • The minimum cost limit is $1; the minimum token limit is 100 tokens.
  • Limits apply only to requests made after the limit is set; they do not apply retroactively.
  • Limits apply until exhausted or reset.
  • Budget limits work for all AI Providers created from this integration.
Budget limits cannot be edited once set

Once set, budget limits cannot be edited by any organization member. Decide the amount, type, and reset cadence deliberately before saving.

Verification

Each provisioned workspace has the intended budget type, amount (at or above the $1 or 100-token minimums), and reset cadence, and you accepted the values knowing they are not editable afterward.

▶ Step 3.7: Add rate limits

Rate limits control the velocity of API usage, protecting against runaway processes and ensuring fair resource distribution across teams.

  1. In the workspace's Set Value panel (opened in Step 3.5), switch on Add Rate Limit.
  2. Choose the limit type with the Request or Token selector:
    • Request-based — limit the number of API calls (for example, 1000 requests per minute).
    • Token-based — limit the token consumption rate (for example, 1M tokens per hour).
  3. Enter the limit in Set Rate Limit and choose the time window in the unit dropdown next to it (shown as Requests/Minute):
    • Per Minute — limits reset every minute, ideal for fine-grained control.
    • Per Hour — limits reset hourly, providing balanced usage control.
    • Per Day — limits reset daily, suitable for broader usage patterns.
  4. Click Apply to save the workspace's limits.

The Add Rate Limit section appears in the Set Value panel shown in Step 3.5.

Key considerations for rate limits:

  • Setting the limit to 0 disables the provider.
  • Rate limits apply immediately after being set.
  • Rate limits work for all providers available on AI Gateway and apply to all organization members who use the provider.
  • After a rate limit is reached, requests are rejected with a specific error code until the time period resets; error messages clearly indicate that the rate limit has been exceeded.

Common use cases:

  • Cost Control — prevent unexpected usage spikes that could lead to high costs.
  • Performance Management — ensure your application maintains consistent performance.
  • Fairness — distribute API access fairly across teams or users.
  • Security — mitigate potential abuse or denial-of-service behavior.
  • Provider Compliance — stay within the rate limits imposed by underlying AI providers.
Rate limits cannot be edited once set

Once set, rate limits cannot be edited by any organization member. Model your peak legitimate traffic before committing a value, and remember that 0 turns the provider off entirely.

Verification

Rate limits reflect measured or expected peak usage per workspace, and nothing is unintentionally set to 0.

▶ Step 3.8: Configure model provisioning and create the integration

Model lists are tied to integrations. When you create an integration, you control which models are available: all AI Providers created from it will only have access to the models you enable. This is essential for:

  • Controlling costs — restrict access to expensive models.
  • Ensuring compliance — limit models to approved ones.
  • Maintaining consistency — standardize model usage across teams.
  1. Click Next: Select Models to advance to the Select Models to Provision stage.
  2. Toggle on the models you want to enable, either individually or with Select All (a search filter helps on long lists). The models you leave off stay unavailable to workspaces, forming your allowlist. Unlike budgets and rate limits, you can change the model list anytime.
  3. Click Set Pricing on a model as needed. The Update Base Model panel opens with an Add custom pricing for this model? toggle; when enabled you can set Input Cost, Output Cost, Cache Pricing (as JSON, for cache write and cache read token prices), and an optional per-model Custom Host. Left unspecified, the model uses default public pricing. Click Apply.
  4. Optionally switch on Automatically enable new models from this provider: new models the provider releases become available on this integration by default, and you can disable them later.
  5. If a model you need is not in the list, click + Add Model (top right).
  6. Click Create Integration.

Phase 4: Guardrails & Logging

With traffic flowing, two operational layers remain: the guardrails the gateway applies to AI interactions, and the two-tier logging pipeline that feeds dashboards, SIEM tooling, and compliance storage.

Verification

Your security requirements are mapped: each needed detection is either covered by a gateway guardrail (Basic or third-party) or explicitly assigned to AI Runtime, with no silent gaps.

▶ Step 4.2: Route event logs to your SIEM and dashboards

AI Gateway separates logs into two categories with different storage and routing strategies. The first category, event logs, are small, structured logs built for real-time SIEM and SOAR ingestion. They include audit events, authentication events, traffic logs, and metrics and analytics.

AttributeEvent Logs
StorageAI Gateway native; SLS (Threat Logs)
Retention1 year
DashboardsAI Gateway dashboard; Strata Logging Service dashboard (Threat Logs)
ExportOpenTelemetry-compatible endpoints; export from SLS (Hybrid and SaaS)
  1. Open the AI Gateway dashboard and confirm audit, authentication, and traffic events are appearing.
  2. Check the SLS dashboard for Threat Logs (this is what the TSG mapping in Step 1.4 enabled).
  3. If you use a SIEM or SOAR platform, point it at the gateway's OpenTelemetry-compatible endpoints, or export from SLS.
Verification

Events generated by test traffic show up in the AI Gateway dashboard, Threat Logs land in SLS, and your SIEM receives the OpenTelemetry stream if configured.

▶ Step 4.3: Manage prompt logs and compliance export

The second category, prompt logs, are large, text-heavy logs capturing full LLM context windows. They are routed to observability tooling for performance analysis, cost tracking, and compliance storage.

AttributePrompt Logs
StorageAI Gateway native
Retention1 year
DashboardsAI Gateway dashboard
ExportLocal export to customer-owned S3 bucket (Hybrid only)
  1. Review prompt logs in the AI Gateway dashboard and confirm full request and response context is captured for test traffic.
  2. Hybrid deployments only: configure local export to your customer-owned S3 bucket if compliance requires prompt retention in your own storage.
S3 export is Hybrid-only

Prompt log export to a customer-owned S3 bucket is available only on Hybrid deployments. If your compliance program requires prompt logs in your own storage, that requirement decides the deployment model back in the Choose Your Deployment Model section.

Verification

Prompt logs for test traffic are visible with full context, and Hybrid tenants see objects arriving in their S3 bucket if export is configured.

▶ Step 4.4: Final end-to-end verification

Walk the whole chain once before handing the gateway to teams:

  1. License — the deployment profile shows flex credit consumption as test traffic flows.
  2. Gateway — the data plane is active (SaaS) or registered and healthy in SCM (Hybrid).
  3. Integration — a provisioned workspace sees the provider in its Model Catalog and can invoke an allowed model without holding provider credentials.
  4. Controls — a request to a model outside the allowlist fails, and traffic past a rate limit is rejected with a clear rate-limit error until the window resets.
  5. Logs — the interaction appears as an event log and a prompt log, and Threat Logs reach SLS.
Verification

Deployment is complete. AI traffic routes through the Prisma AIRS AI Gateway with credentials centralized, models allowlisted, spend guarded by budgets and rate limits, and every interaction logged to the dashboard, SLS, and your SIEM.
