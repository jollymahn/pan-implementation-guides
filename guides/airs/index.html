Prisma AIRS Platform Overview

How API Intercept, Network Intercept, AI Gateway, and AI Model Security work together, and where inspection actually happens.

Prisma AIRS (AI Runtime Security) is Palo Alto Networks' multi-layer platform for securing AI applications, AI models, and AI agents. It addresses threats that traditional network security cannot: prompt injection, sensitive data leakage through LLMs, model supply-chain attacks, and rogue AI agent behavior.

How to use this page

Click any shaded box in the flow diagrams to open a detail panel with exact API endpoints, protocols, config options, and gotchas. Each section covers one integration path end-to-end.

Strata Cloud Manager (SCM) as the Management Plane

Every AIRS component is configured, monitored, and managed through Strata Cloud Manager. SCM is not an inspection point; it is the operator control plane that connects licensing, policy, and telemetry for all pillars.

What SCM Does for AIRS

  • API Intercept: Register AI applications, generate API keys, configure security profiles, view scan logs (AI Security > AI Runtime > API Applications)
  • Network Intercept: Generate Terraform templates to deploy AIRS Firewalls, create AI Security Profiles, create and push Security Policy Rules to firewalls, view AI security logs
  • AI Gateway: Configure LLM integrations (provider, API key, slug, custom host), set workspace budgets and rate limits, manage model allowlists, view event and prompt logs
  • Cloud Account Onboarding: Connect AWS/Azure/GCP accounts via IAM Terraform for automated workload and AI-asset discovery (Agent Discovery, SLR reports)
  • Licensing: Activate the AIRS license, link Deployment Profiles to a Tenant Service Group (TSG), and link Strata Logging Service (SLS) to the same TSG

Panorama vs. SCM: Management Boundaries

AIRS Firewall VMs (used by Network Intercept, K8s & Containers, and Microperimeter) support Panorama management (requires Panorama 11.2.5+). The remaining pillars are SCM-only: API Intercept, AI Gateway, Model Security, Red Teaming, and Agent Discovery.

⚠️ Common API Intercept Pitfalls
API key is region-locked

Each key works only in the region where it was created. Using a US key from an EU-deployed app returns an auth error. Generate a separate key per region in SCM.

2 MB payload limit on sync scans

Long multi-turn conversations or large document RAG contexts can easily exceed 2 MB. Use the async endpoint (5 MB limit) for large payloads, or truncate context before scanning.

Masking requires Basic DLP + Block

Data masking (replacing sensitive spans with "X") only works with the Basic DLP profile AND the action set to Block. Advanced Enterprise DLP profiles and Alert actions do not produce masked output.

Grounding requires a context field

Contextual grounding (hallucination detection) only fires if you include the context parameter in the scan request. Omitting it skips the check silently.

The firewall decapsulates, inspects, and if AI traffic is detected, forwards content to the PAN AI Security cloud for deeper analysis before returning a verdict.

MTU Impact: panredirect reduces MTU to 1440

GENEVE encapsulation adds overhead, reducing effective MTU from 1500 to 1440 on the pangnv0 interface. Docker bridge networks default to MTU 1500, so container traffic will break unless MTU is also reduced to 1440. Plan accordingly before enabling panredirect enable on interfaces serving containerized workloads.

⚠️ Common Network Intercept Pitfalls
MTU drop breaks containers

GENEVE overhead reduces MTU from 1500 to 1440. Docker bridge networks default to 1500. Reduce container MTU to 1440 before enabling panredirect, or containerized AI traffic will silently drop packets mid-stream.

Enabling on mgmt NIC locks out SSH

panredirect intercepts all traffic on the enabled interface, including SSH. Configure steering rule exceptions for your jump host or bastion IP addresses before enabling redirection on the management interface.

All AI content inspected in the US

Even if the AIRS Firewall is deployed in eu-west-1, AI content is forwarded to the PAN AI Security cloud in the US for analysis. Evaluate GDPR and sector-specific data residency requirements before deploying on EU-resident workloads.

Cloud Management requires a support ticket

You cannot self-serve enable SCM Cloud Management for Network Intercept. Open a support case with your TSG ID, tenant name, and region before starting deployment.

AI Gateway: Centralized LLM Proxy

AI Gateway acts as a proxy between AI applications and LLM providers. Instead of calling OpenAI or Anthropic directly, applications call the AI Gateway endpoint. The gateway enforces workspace budgets, rate limits, model allowlists, and basic guardrails, and logs every interaction for auditability. PII detection and deep threat scanning are handled by API Intercept, not AI Gateway.

⚠️ Common AI Gateway Pitfalls
No DLP or injection detection

AI Gateway guardrails do not include DLP or prompt injection. Users sometimes assume proxy = full security. It is not. Pair AI Gateway with API Intercept in your app code for complete coverage.

Prompt logs are NOT in SCM Log Viewer

Full prompt/response content is stored in AI Gateway Native only, not in Strata Logging Service. You cannot search prompt content from SCM Log Viewer. To keep prompt logs in your own infrastructure, use Hybrid deployment with S3 export.

HTTP 429 gives no retry hint

When a workspace hits its rate or budget limit, AI Gateway returns HTTP 429 with no Retry-After header. Applications need explicit exponential backoff logic, or users will see silent failures.

AI Model Security: Pre-Deployment Scanning

AI Model Security scans ML model artifacts before they reach production. This is a pre-deployment gate, not a runtime tool. A developer or CI pipeline calls the Model Security CLI or Python SDK with a model URI and a security group. The PAN scanning service downloads the model, evaluates it against all enabled rules, and returns a PASS or FAIL verdict with PAIT threat codes for any violations.

⚠️ Common AI Model Security Pitfalls
Private HF repos can't be scanned directly

The Model Security API cannot access private Hugging Face repositories. Download the model locally first, then scan it as a Local Disk source with the same CLI or SDK.

Scans are permanent audit records

Completed scans cannot be deleted. Build your security group configuration carefully before running scans in production, and use a test security group during initial setup.

Non-blocking rules won't fail the CI gate

Rules configured as non-blocking generate findings but do not set aggregate_eval_outcome to FAIL. If you want the CI pipeline to block on a rule, verify it is configured as blocking in the Security Group, not just enabled.

K8s & Container Protection: PAN-CNI

For Kubernetes workloads, AIRS uses the PAN Container Networking Interface (PAN-CNI) plugin instead of a standalone panredirect agent. PAN-CNI is deployed via Helm to each K8s node and intercepts pod-level network traffic at the node. A Tag Collector DaemonSet discovers pod IP-to-label mappings from the cloud provider (AWS VPC CNI or Azure CNI) and pushes them to the AIRS Firewall, enabling policy that targets specific pod workloads by Kubernetes label.

⚠️ Common K8s & Container Pitfalls
PAN-CNI replaces or chains with existing CNI

PAN-CNI must be configured to chain with your existing CNI plugin (Flannel, Calico, etc.). Installing without chaining breaks pod networking. Verify the CNI chain order in the Helm values before deploying.

Tag Collector requires cloud-provider IAM

The Tag Collector DaemonSet needs IAM permissions to read VPC/subnet tags from AWS or Azure. Missing permissions cause silent failures where pod IPs are not mapped to labels and policy falls back to IP-only matching.

MTU applies to pod interfaces too

GENEVE overhead reduces effective MTU from 1500 to 1440 on pod interfaces. Pods with jumbo-frame workloads or misconfigured MTU will experience packet drops under load.

⚠️ Common Microperimeter Pitfalls
Always set steering exceptions before enabling

Run panredirect rule insert to exclude your management IP, jump host, and any monitoring agents before calling panredirect enable. Once enabled, all traffic on that interface is redirected, including SSH.

pangnv0 MTU applies to all redirected traffic

The GENEVE interface pangnv0 has MTU 1440. Any application on the redirected interface that assumes MTU 1500 will silently drop large packets. Set the interface MTU explicitly before enabling redirection.

health_check before enable

Always run panredirect health_check to confirm GENEVE tunnel connectivity to the AIRS Firewall before calling panredirect enable. If the firewall is unreachable, enabling redirection will black-hole all outbound traffic on that interface.

⚠️ Common Red Teaming Pitfalls
Run it after deploying defenses, not before

Red Teaming measures whether your deployed defenses (API Intercept, Network Intercept) are working. Running it on an unprotected application tells you the app is vulnerable, which you already know. Run it post-deployment to validate coverage gaps.

Private endpoints need connectivity pre-configured

If your target AI app is not publicly reachable, you must set up VPN or private link connectivity to the PAN Red Teaming platform before starting a session. This cannot be configured mid-test.

Rate limits on the target can skew results

If your AI application rate-limits incoming requests aggressively, many attack probes will be throttled (HTTP 429) before the evaluator can assess the response. Temporarily raise rate limits on the target during a red team session, or coordinate the test window with your ops team.

How Verdicts Are Generated

Each AIRS pillar uses a different verdict mechanism. Here is how each one scores content and issues an action decision.

API Intercept Verdict Logic

The Scan API runs multiple independent detection engines in parallel. Each engine returns a boolean flag (true / false). The overall action field is determined by the security profile: if any enabled engine fires with action = Block, the overall verdict is block.

✅ Action: allow

No block-configured engine fired. Content is safe to pass to the LLM or return to the user. category = "benign".

🚫 Action: block

At least one block-configured engine fired. category = "malicious". Data masking (for DLP) replaces sensitive spans with "X" characters in the API response.

The full response contains per-detection booleans so the application can log exactly which engine triggered and why:

{
  "action": "block",
  "category": "malicious",
  "prompt_detected": {
    "injection": true,
    "dlp": false,
    "url_cats": false,
    "toxic_content": false,
    "db_security": false,
    "malicious_code": false
  },
  "response_detected": {
    "dlp": false,
    "url_cats": false,
    "agent": false,
    "topic_violation": false
  },
  "scan_id": "...",
  "report_id": "..."
}

Network Intercept Verdict Logic

The AIRS Firewall identifies AI traffic by matching against known LLM endpoint URLs (or all traffic if Custom Model Support is enabled). Recognized AI traffic is forwarded to the PAN AI Security cloud. The cloud returns a verdict and the firewall enforces the action configured in the Security Policy Rule:

✅ Allow

Traffic passes. An AI Security Log entry may still be generated if the action is "alert."

⚠️ Alert

Traffic passes but an AI Security Log is written to SLS asynchronously. No inline disruption.

🚫 Block

Firewall drops packets and sends a TCP reset. PAN-OS 11.2.11+ supports a custom HTTP error response instead of a bare TCP reset.

If the PAN AI Security cloud takes longer than Max Inline Latency (configurable 1–300 seconds), the Inline Timeout Action fires (Allow, Alert, or Block). This prevents inspection latency from disrupting user-facing AI applications.

AI Model Security Verdict Logic

The scanning service evaluates all enabled rules in the Security Group. Each rule is either blocking or non-blocking:

  • Blocking rule violation: model FAILS. CI pipeline should reject the model.
  • Non-blocking rule violation: model passes but a finding is returned. Use for informational checks.

The response includes an aggregate_eval_outcome (PASS/FAIL), severity counts (critical/high/medium/low), and a violations array with PAIT threat codes, affected file hashes, and remediation guidance.

Detection Engines — Technical Detail

▶ Prompt Injection Engine

Detects attempts to manipulate LLM behavior through crafted inputs: overriding system prompts, extracting training data, or issuing hidden instructions via injected text. Supported in prompts, responses, and MCP tool events. Coverage: 9 languages (English, Spanish, Russian, German, French, Japanese, Portuguese, Italian, Simplified Chinese). Hindi and Traditional Chinese in preview.

API field: prompt_detected.injection (boolean)

▶ DLP (Data Loss Prevention)

Detects PII, credentials, financial data, healthcare data, and other regulated content in prompts and responses. Two modes:

  • Basic DLP: Predefined patterns for common data types. Supports data masking in API responses (replaces sensitive spans with "X" characters). Blocking action required for masking.
  • Advanced Enterprise DLP: Full enterprise DLP profile integration. Does NOT support response masking.

API field: prompt_detected.dlp, response_detected.dlp (boolean)

▶ Contextual Grounding (Hallucination Detection)

Checks whether the LLM's response introduces facts or conclusions not present in the provided context document. Used for RAG (Retrieval-Augmented Generation) pipelines where factual accuracy is critical. Response-only; cannot check prompts.

Requires the scan API call to include a context field containing the reference document the LLM was given. Returns grounded or ungrounded.

Not available for MCP tool event scans

Contextual grounding is not supported when scanning MCP tool events (tool_event payloads).

▶ AI Agent Protection

Detects threats specific to agentic AI systems operating with tools, memory, and multi-step autonomy:

  • Function schema leakage: LLM response exposes the agent's tool definitions to the user
  • Direct tool invocation: Attempts to call internal tools from outside the agent flow
  • Memory tampering: Injecting false memories into the agent's persistent context
  • Context poisoning (MCP): Injecting malicious instructions through MCP tool responses
  • Credential leakage (MCP): Leaking tokens or credentials through tool outputs

Requires configuring an AI Agent framework in the API Intercept application definition in SCM. Without this, only model-based (not pattern-based) agent protections apply.

API field: response_detected.agent (boolean)

Data Residency

All AI content inspection routes to the US

Regardless of where the AIRS Firewall is deployed (eu-west-1, ap-southeast-1, etc.), AI content is forwarded to the Palo Alto Networks AI Security cloud service in the US region for analysis. The same applies to API Intercept. This has data residency implications for EU-regulated data (GDPR) and sector-specific regulations. The official PAN documentation does not address this gap directly. Evaluate with your compliance team before deploying AIRS to inspect EU-resident data.

SLS (Strata Logging Service) allows region selection at activation time (US, UK, India, Canada, Singapore). Logs can be stored in the customer's chosen SLS region. However, the AI scoring that produces those logs still occurs in the US.
