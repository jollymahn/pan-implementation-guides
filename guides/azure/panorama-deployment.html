Panorama Deployment on Azure

End-to-end guide: Azure subscription setup through Panorama deployment to verified management platform access

AWS Panorama Guide GCP Panorama Guide
Phase 1 Prerequisites Phase 2 Terraform Config Phase 3 Deploy & Verify Phase 4 Post-Deploy Phase 5 Verification
Guide Approach

This guide deploys a standalone Panorama instance on Azure for centralized management of Palo Alto Networks firewalls. Panorama is deployed in management-only mode (no additional logging disks by default) into a dedicated VNet with a public IP on the management interface.

Deployment method: All Azure infrastructure is deployed with Terraform using the official Palo Alto Networks SWFW Modules for Azure. The panorama_standalone example from the terraform-azurerm-swfw-modules repository provides the reference configuration.

Default authentication: Username panadmin with an auto-generated random password (available via Terraform outputs). SSH key authentication is optionally supported.

Architecture Overview

Before deploying, review the target architecture. This is a non-zonal deployment of a single Panorama instance. The infrastructure consists of:

  • A VNet with one subnet dedicated to the Panorama appliance
  • A Network Security Group (NSG) restricting access to the Panorama management interface
  • A public IP assigned to the management interface for direct access
  • An optional Availability Set for non-zonal HA deployments
▶ Topology

The Panorama standalone deployment is intentionally minimal. A single VNet (10.1.0.0/27) hosts one subnet (10.1.0.0/28) for the Panorama management interface. An NSG on the subnet restricts inbound access to SSH (TCP 22) and HTTPS (TCP 443) from a specified allowlist.

ComponentDefault ValuePurpose
VNet10.1.0.0/27Panorama management network
Panorama Subnet10.1.0.0/28Management interface NIC
Private IP10.1.0.10Static IP for the Panorama management interface
Public IPAuto-assignedExternal access to SSH and HTTPS
NSGpanorama-nsgInbound allow on TCP 22, 443 from admin CIDR
VM SizeStandard_D5_v216 vCPU, 56 GB RAM — minimum for production Panorama
Firewall device management ports

If VM-Series firewalls will register to this Panorama, the NSG must also allow inbound TCP 3978 (management plane) and TCP 28443 (device certificate) from the firewall management subnet CIDR. Add these rules to the vnets variable in your terraform.tfvars before deploying.

Logging disks

This example deploys with one data disk configured. For production environments that require local log storage on Panorama, configure additional logging disks via the logging_disks property. See the Panorama module documentation for available options.

▶ Terraform Modules Used

The panorama_standalone example composes three modules from the terraform-azurerm-swfw-modules repository:

ModulePurpose
vnetCreates the VNet, subnet, NSG, and route tables
public_ipCreates and manages public IP addresses
panoramaDeploys the Panorama VM, network interfaces, and optional logging disks

Additionally, the example uses the random provider to auto-generate a password and the azurerm provider (v4+) for all Azure resource management.

▶ Step 1.3: Obtain Panorama License

Each Panorama instance requires a valid license. All cloud deployments use the BYOL (Bring Your Own License) model.

Option A: Existing License

  1. Log in to the Customer Support Portal.
  2. Navigate to Products > Assets and locate your Panorama serial numbers or auth codes.
  3. Confirm you have one license per Panorama instance (two licenses for an HA pair).

Option B: Provision from Flex Credits

If your organization uses a Palo Alto Networks flex credit profile, you can provision a Panorama license directly from your credit pool.

  1. Log in to the Customer Support Portal.
  2. Navigate to Products > Flex Credits.
  3. Select Provision and choose Panorama as the product.
  4. Select the desired management capacity and license term.
  5. Complete the provisioning — an auth code is generated and appears under Products > Assets.
Note

License activation happens after deployment in Phase 4. At this stage, confirm the license exists in your support portal account — activation requires the Panorama instance to be running and have internet connectivity.

Verification

Your Panorama auth codes or serial numbers are visible in the Customer Support Portal under Products > Assets.

▶ Step 1.5: Set Azure Subscription ID

The AzureRM provider (v4+) requires an explicit subscription ID. Setting it as an environment variable keeps the value out of version-controlled files.

# Get your subscription ID
az account show --query id -o tsv

# Export it as an environment variable
export ARM_SUBSCRIPTION_ID="your-subscription-id"
Do not put the Subscription ID in tfvars

The example.tfvars has a subscription_id field set to null. Leave it as null and use the ARM_SUBSCRIPTION_ID environment variable instead. Putting the Subscription ID in clear text inside committed code is a security risk.

Verification

Run echo $ARM_SUBSCRIPTION_ID — the output matches the subscription ID from az account show.

▶ Step 2.4: Configure VNet & Subnet

The vnets variable defines the VNet, subnet, and NSG for Panorama. The critical customization is the NSG source_address_prefixes — replace the placeholder with your actual admin IP ranges.

# NETWORK

vnets = {
  "vnet" = {
    name          = "panorama-vnet"
    address_space = ["10.1.0.0/27"]
    network_security_groups = {
      "panorama" = {
        name = "panorama-nsg"
        rules = {
          mgmt_inbound = {
            name                       = "panorama-management-allow-inbound"
            priority                   = 100
            direction                  = "Inbound"
            access                     = "Allow"
            protocol                   = "Tcp"
            source_address_prefixes    = ["203.0.113.0/24"]  # TODO: Your admin IPs
            source_port_range          = "*"
            destination_address_prefix = "10.1.0.0/28"
            destination_port_ranges    = ["22", "443"]
          }
        }
      }
    }
    subnets = {
      "panorama" = {
        name                       = "panorama-snet"
        address_prefixes           = ["10.1.0.0/28"]
        network_security_group_key = "panorama"
      }
    }
  }
}
Replace the placeholder admin IP

The example uses 1.1.1.1/32 as a placeholder for source_address_prefixes. Replace this with your actual admin network CIDR. Leaving the placeholder means Panorama will be unreachable after deployment.

Add device management ports for firewalls

If VM-Series firewalls will register to this Panorama, add a second NSG rule allowing inbound TCP 3978 and 28443 from the firewall management subnet CIDR. Without these ports, firewalls cannot connect to the Panorama management plane.

Verification

The source_address_prefixes value contains your actual admin network CIDR (not the placeholder). The subnet CIDR fits within the VNet address space.

▶ Step 2.5: Configure the Panorama Instance

The panoramas variable defines the Panorama VM: name, authentication, PAN-OS image version, VM size, network interfaces, and optional logging disks.

# PANORAMA

panoramas = {
  "pn-1" = {
    name     = "panorama01"
    vnet_key = "vnet"
    authentication = {
      disable_password_authentication = false
      # ssh_keys = ["~/.ssh/id_rsa.pub"]  # Uncomment for SSH key auth
    }
    image = {
      version = "11.1.607"
    }
    virtual_machine = {
      size      = "Standard_D5_v2"
      zone      = null                   # null for non-zonal deployment
      disk_name = "panorama-os-disk"
    }
    interfaces = [
      {
        name               = "management"
        subnet_key         = "panorama"
        private_ip_address = "10.1.0.10"
        create_public_ip   = true
      }
    ]
    logging_disks = {
      "datadisk1" = {
        name = "data-disk1"
        lun  = "0"
      }
    }
  }
}

Password auto-generation

When password is left as null (or omitted), Terraform generates a random 16-character password using the random_password resource. Retrieve it after deployment with terraform output password. The password includes uppercase, lowercase, numeric, and special characters (_%@).

SSH key authentication

To use SSH key authentication instead of (or in addition to) password: uncomment the ssh_keys line and provide the path to your public key. To disable password authentication entirely, set disable_password_authentication = true — in that case, ssh_keys is required.

Verification

The panoramas block has the correct vnet_key matching the key in the vnets variable. The subnet_key in the interface block matches a subnet key defined in vnets. The private_ip_address falls within the subnet CIDR.

▶ Step 2.6: Optional — Configure Availability Set

For non-zonal HA deployments, an Availability Set provides fault and update domain isolation. This is only needed when deploying multiple Panorama instances without using Availability Zones.

# Uncomment and add to terraform.tfvars for HA deployments
availability_sets = {
  "panorama-as" = {
    name                = "panorama-avset"
    update_domain_count = 5
    fault_domain_count  = 2
  }
}

Then reference the Availability Set in the panoramas block by adding avset_key = "panorama-as" to the virtual_machine object.

Region-dependent fault domain count

Not all Azure regions support the same number of fault domains. Verify fault domain support for your target region before deploying. Small regions (without Availability Zones) may support only 2 fault domains.

Verification

If using an Availability Set: the availability_sets variable is defined and the Panorama virtual_machine.avset_key references the correct key. If not using one: the availability_sets variable is omitted or empty.

Phase 4: Post-Deployment

Panorama needs several minutes to boot after the VM is created. This phase covers initial access, password change, and license activation.

▶ Step 4.1: Wait for Panorama to Boot

After terraform apply completes, the Panorama VM is provisioned but the PAN-OS software still needs to boot. This takes approximately 5–10 minutes.

Monitor the boot progress:

  1. In the Azure Portal, navigate to the Panorama VM.
  2. Under Help, click Boot diagnostics to view the serial console output.
  3. Wait until the console shows the PAN-OS login prompt.

Alternatively, poll the management interface from the command line:

# Replace with your Panorama public IP
PANORAMA_IP=$(terraform output -json panorama_mgmt_ips | jq -r '."pn-1"')

# Poll until HTTPS responds (timeout after 10 min)
until curl -sk --connect-timeout 5 "https://${PANORAMA_IP}" -o /dev/null 2>&1; do
  echo "Waiting for Panorama to boot..."
  sleep 30
done
echo "Panorama is ready at https://${PANORAMA_IP}"
Verification

curl -sk https://${PANORAMA_IP} returns an HTML page (the Panorama login form), or the Azure Boot diagnostics show the PAN-OS login prompt.

▶ Step 4.2: SSH into Panorama

Verify CLI access using the auto-generated credentials.

PANORAMA_IP=$(terraform output -json panorama_mgmt_ips | jq -r '."pn-1"')
PANORAMA_PASS=$(terraform output -raw password | jq -r '."pn-1"')

ssh panadmin@${PANORAMA_IP}

When prompted, enter the auto-generated password from terraform output password.

First SSH connection

The first connection will prompt to accept the host key fingerprint. Type yes to continue.

Verification

The SSH session connects and displays the PAN-OS CLI prompt: panadmin@panorama01>

▶ Step 4.3: Access the Web UI

Access the Panorama Web UI for graphical management.

  1. Open a browser and navigate to https://<PANORAMA_PUBLIC_IP>.
  2. Accept the self-signed certificate warning (expected on first access).
  3. Log in with username panadmin and the auto-generated password from terraform output password.
Self-signed certificate

The initial HTTPS connection uses a self-signed certificate. This is expected. Replace it with a CA-signed certificate after initial setup for production use.

Verification

The Panorama dashboard loads and displays system information including the PAN-OS version, serial number, and uptime.

▶ Step 4.4: Change the Default Password

The auto-generated password is stored in Terraform state. Change it immediately to reduce exposure.

Option A: Web UI

  1. Navigate to Panorama > Administrators.
  2. Click panadmin.
  3. Enter the current password in Current Password.
  4. Enter and confirm a new password that meets complexity requirements.
  5. Click OK, then Commit.

Option B: CLI

configure
set mgt-config users panadmin password
# Enter new password when prompted
commit
Break-glass account

Before changing the default password, consider creating a separate break-glass administrator account with a strong, documented password stored in a vault. If LDAP/SAML authentication is configured later and fails, this local account provides emergency access. Account lockout applies to all local accounts — failed login attempts will lock the account after the configured threshold.

Verification

Log out and log back in with the new password. The login succeeds.

▶ Step 4.5: Activate the Panorama License

Panorama ships unlicensed. Activate the license to enable device management, logging, and full feature access.

Option A: Web UI

  1. Navigate to Panorama > Licenses.
  2. Click Activate feature using authorization code.
  3. Enter the Panorama auth code from Phase 1, Step 1.3.
  4. Click OK.
  5. Panorama will contact the licensing server and activate. This requires outbound internet access from the management interface.

Option B: CLI

request license fetch
Outbound internet required

License activation contacts updates.paloaltonetworks.com over HTTPS. The management interface must have outbound internet access. The public IP assigned by Terraform provides this. If using a private-only deployment, configure a NAT Gateway on the Panorama subnet.

Verification

Navigate to Panorama > Licenses. The license status shows as Active with the correct feature set and expiration date.

Troubleshooting

▶ Marketplace Terms Not Accepted
SymptomCauseResolution
terraform apply fails with MarketplacePurchaseEligibilityFailed Azure Marketplace terms for Panorama BYOL not accepted in this subscription Run the marketplace terms acceptance command: 
az vm image terms accept \
  --publisher paloaltonetworks \
  --offer panorama \
  --plan byol

Then re-run terraform apply.

▶ Cannot SSH to Panorama
SymptomCauseResolution
SSH connection times out NSG source_address_prefixes does not include your IP Verify your public IP is within the NSG allowlist. Update terraform.tfvars and re-apply if needed.
SSH connection refused Panorama still booting Wait 5–10 minutes after terraform apply. Check Azure Boot diagnostics for progress.
SSH password rejected Password mismatch Retrieve the correct password with terraform output password. Ensure terraform.tfvars did not override the auto-generated password with an incorrect value.
▶ Web UI Not Accessible
SymptomCauseResolution
Browser times out on https://<IP> Port 443 blocked by NSG Verify the NSG rule includes port 443 in destination_port_ranges and your IP in source_address_prefixes.
Browser shows connection refused Panorama web service not yet started Panorama boots the web service after the CLI is available. Wait an additional 2–3 minutes after SSH becomes accessible.
No public IP assigned create_public_ip = false in interface config Set create_public_ip = true in the management interface block and re-apply. Alternatively, use a jump host or VPN to access the private IP.
▶ License Activation Fails
SymptomCauseResolution
License activation times out or returns error No outbound internet from management interface Verify the Panorama management interface has a public IP (provides outbound NAT) or a NAT Gateway on the subnet. Panorama must reach updates.paloaltonetworks.com on TCP 443.
Invalid auth code Wrong auth code or expired license Verify the auth code in the Customer Support Portal under Products > Panorama. Confirm the license is not expired.

Test outbound connectivity from the Panorama CLI:

request license fetch
# Or test DNS/connectivity:
ping host updates.paloaltonetworks.com
▶ Terraform Provider Authentication Errors

AuthorizationFailed Insufficient permissions on the subscription Verify the authenticated identity has Contributor role. Run az role assignment list --assignee <your-user-or-sp> to check.

Cleanup

▶ Destroy All Resources

Remove all Azure resources created by this deployment.

terraform destroy -var-file=terraform.tfvars

Terraform will display the resources to be destroyed. Type yes to confirm.

Data loss warning

Destroying the Panorama VM permanently deletes all configuration, device groups, templates, logs, and managed device state stored on the instance. Export the running configuration (Panorama > Setup > Operations > Export named configuration snapshot) before destroying if the data is needed.

Verification

Terraform reports Destroy complete! Resources: ~10 destroyed. The resource group no longer appears in the Azure Portal.
