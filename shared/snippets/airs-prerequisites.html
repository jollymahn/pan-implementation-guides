▶ Step {{phaseId}}.5 — Cloud-Specific Prerequisites

Prepare the following for your target cloud provider(s). These apply regardless of deployment model.

Choose your path Cloud Provider Select your cloud provider to see the required pre-deployment resources and IAM setup.

Account & Infrastructure

  • AWS account with administrative access to create IAM roles, policies, VPCs, and EC2 instances
  • Subscribe to the Prisma AIRS image in AWS Marketplace (same listing as VM-Series due to Universal Image)
  • IAM permissions to create CloudFormation stacks or Terraform resources
  • VPC with management, data, and HA subnets planned
  • Terraform > 1.3 and < 2.0

S3 Bucket for Discovery Logs

  1. Navigate to S3 in the AWS Management Console.
  2. Click Create bucket. The bucket region must match the region where your AI models run.
  3. Enter a unique bucket name and click Create bucket.

VPC Flow Logs

  1. Navigate to VPC Dashboard → Subnets.
  2. Select the subnet for your application VPC and open the Flow logs tab.
  3. Create or edit a flow log:
    • Destination: Send to the S3 bucket created above (enter the bucket ARN)
    • Log record format: Custom Format — select all Standard attributes
    • Partition logs by time: Every 1 hour (60 mins)

Amazon Bedrock Model Invocation Logging

  1. In the AWS Bedrock Console, navigate to Settings under Bedrock Configurations.
  2. Toggle Model invocation logging to enable.
  3. Choose S3 only as the logging destination.
  4. Select the S3 bucket created above and click Save settings.

EKS Authentication (if using EKS)

  1. In the EKS Console, click your cluster → Access tab → Manage access.
  2. Under Cluster authentication mode, select EKS API and ConfigMap.
  3. If Public endpoint access is enabled, add these IP addresses under Advanced settings:
# Default SCM discovery IPs
34.71.64.3/32
34.28.60.186/32

# Germany / Netherlands region
34.32.8.22/32

# Australia region
34.116.76.243/32

IAM Role for VM Model Invocation

  1. In IAM, create a role with a trust policy allowing ec2.amazonaws.com to assume the role.
  2. Attach the bedrock:InvokeModel permission to the role:
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "bedrock:InvokeModel",
    "Resource": "*"
  }]
}

Pod Identity Associations (if using EKS)

  1. In the EKS Console, select your cluster → Access → Pod Identity associations.
  2. Assign IAM roles to Kubernetes service accounts so pods can access AI model endpoints.

Enable Network Watcher

  1. In the Azure Portal, search for Network Watcher.
  2. Select your region and click Enable.

Virtual Network Flow Logs

  1. In Network Watcher, select Flow Logs → + Add flow log.
  2. Select your Subscription. Under Flow log type, choose Virtual network.
  3. Select the Storage Account created above.
  4. Set Retention (days) to 30.
  5. Click Review + Create → Create.

Azure OpenAI Diagnostic Settings

  1. In the Azure Portal, open your OpenAI resource.
  2. Navigate to Diagnostic settings → Add diagnostic setting.
  3. In log categories, select Request and Response Logs.
  4. Enable Archive to a storage account and select the Storage Account.
  5. Click Save.
3-Hour Log Delay

Flow logs and audit logs must be older than 3 hours to be scanned. Azure continuously overwrites the log file in the Storage Account, so discovery only scans files three hours after creation to prevent data loss.

Azure Roles (for multi-subscription onboarding)

If onboarding more than one Azure subscription on the same tenant, assign these roles on the onboarding application:

  • Azure Kubernetes Service Cluster User Role
  • Storage Blob Data Reader
  • Reader
Azure Route Table Association

Azure requires manual route table association to steer traffic through the firewall. Plan your UDR (User-Defined Route) configuration before deployment.

Account & Infrastructure

  • gcloud CLI installed

VPC Flow Logs

  1. In the GCP Console → VPC Networks, select the VPC with workloads to protect.
  2. Click the SUBNETS tab and select all subnets where workloads are present.
  3. Click FLOW LOGS → Configure.
  4. Set:
    • Aggregation Interval: 5 Sec
    • Metadata annotations: Enabled
    • Sample rate: 100%
  5. Click SAVE.

Data Access Audit Logs for Vertex AI

  1. In the GCP Console, search for Audit Logs.
  2. Search for and select Vertex AI API.
  3. Enable the Data Read permission type.
  4. Click SAVE.

Cloud Storage Bucket

  1. In Cloud Storage, click CREATE.
  2. Enter a globally unique bucket name.
  3. Choose Multi-region for location type.
  4. Choose Standard for storage class.
  5. Select Uniform access control.
  6. Click CREATE.

Log Router Sink

  1. In the GCP Console, search for Log Router → Create sink.
  2. Enter a sink name. For Sink destination, choose Cloud Storage Bucket and enter the bucket name.
  3. Add this inclusion filter (replace placeholders):
(logName =~ "logs/cloudaudit.googleapis.com%2Fdata_access" AND protoPayload.methodName:("google.cloud.aiplatform.")) OR ((logName="projects/<GCP_PROJECT_ID>/logs/compute.googleapis.com%2Fvpc_flows") AND (resource.labels.subnetwork_name="<SUBNET_1>" OR resource.labels.subnetwork_name="<SUBNET_2>"))
  1. Click Preview logs to verify, then Create sink.

▶ Step {{phaseId}}.6 — Panorama Prerequisites (if using Panorama management)

If you plan to manage AIRS firewalls through Panorama, complete these additional prerequisites. Skip this step if using SCM-only management.

ComponentRequirement
Panorama SoftwareVersion 11.2.5 or above
Prisma AIRS FirewallVersion 11.2.5 or above
CloudConnector PluginVersion 2.1.0
Enterprise DLP PluginVersion 5.0.5 or above
Deployment ModeStandalone or High Availability (HA)

Preparation Steps

  1. Deploy Panorama in standalone or HA mode. Copy and save the active/passive Panorama IP address.
  2. Generate the VM Auth Key on Panorama.
  3. (Optional) For public-cloud firewalls, add the firewall’s public IP under Panorama → Setup → Interfaces → Management.
  4. Install CloudConnector Plugin 2.1.0 and install the Panorama Device Certificate.
  5. Enable and verify the cloud connector plugin:
# Enable the cloud connector
admin@Panorama> request plugins cloudconnector enable basic

# Verify connection status
admin@Panorama> show plugins cloudconnector status

# Expected output:
# pass
# CloudConnector plugin is enabled.
# Connectivity to region ... is a success.
  1. Install Enterprise DLP Plugin 5.0.5 or above on Panorama.
  2. Set Telemetry region to Americas (recommended).
  3. (Optional) Onboard Panorama to Strata Logging Service for log forwarding.
  4. Enable automatic configuration push to managed firewalls on the template stack.
  5. Commit → Commit to Panorama.
Known Limitation: PAN-288025

Panorama cannot centrally manage AIRS image upgrades. Workaround: download the image and manually deploy via the firewall web interface or CLI.

CloudConnector Connection Time

It may take more than 30 minutes for Panorama to connect to Strata Logging Service after enabling the CloudConnector plugin.

Verification

The show plugins cloudconnector status command returns pass. The CloudConnector plugin shows as enabled with successful connectivity.
